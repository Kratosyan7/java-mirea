# Практика №5 — UML-диаграммы

## Композиция: стек СОДЕРЖИТ список (has-a)

```
┌─────────────────────────────┐          ┌──────────────────────┐
│          MyStack            │          │  java.util.ArrayList │
├─────────────────────────────┤          ├──────────────────────┤
│ -list: ArrayList<Object>    │◆────────▶│ +add(o): boolean     │
├─────────────────────────────┤  1     1 │ +get(i): E           │
│ +isEmpty(): boolean         │          │ +remove(i): E        │
│ +getSize(): int             │          │ +size(): int         │
│ +peek(): Object             │          │ +clear(): void       │
│ +pop(): Object              │          │ ...                  │
│ +push(o: Object): void      │          └──────────────────────┘
└─────────────────────────────┘
```

Закрашенный ромб ◆ — композиция. `MyStack` держит `ArrayList` в приватном
поле, поэтому наружу видны только пять методов стека. Методы `ArrayList`
клиенту недоступны.

## Наследование: стек ЯВЛЯЕТСЯ списком (is-a)

```
            ┌──────────────────────┐
            │  java.util.ArrayList │
            ├──────────────────────┤
            │ +add(o): boolean     │
            │ +add(i, o): void     │   ← лишний для стека
            │ +get(i): E           │   ← лишний для стека
            │ +remove(i): E        │
            │ +size(): int         │
            │ +clear(): void       │   ← лишний для стека
            └──────────┬───────────┘
                       △
                       │ extends
            ┌──────────┴───────────┐
            │       MyStack        │
            ├──────────────────────┤
            │ +getSize(): int      │
            │ +peek(): Object      │
            │ +pop(): Object       │
            │ +push(o: Object)     │
            └──────────────────────┘
```

Пустой треугольник △ — наследование. `MyStack` получает ВСЕ публичные методы
`ArrayList`, включая неподходящие: через `add(0, "x")` можно вставить элемент
в середину стека, что нарушает принцип «последним пришёл — первым вышел».
Это видно в выводе `TestMyStack`:

```
После унаследованного add(0, ...): стек: [влезли в середину, один, два]
```

## Вывод

Композиция предпочтительнее: она позволяет определить совершенно новый класс
для моделирования стека, не наследуя ненужные и неподходящие методы
`ArrayList`. Наследование здесь нарушает принцип подстановки — `MyStack` не
является корректной заменой `ArrayList` и наоборот.

## GenericStack<E> на массиве (задание №2, пункт 1)

```
┌────────────────────────────────────┐
│         GenericStack<E>            │
├────────────────────────────────────┤
│ -elements: Object[]                │  массив для хранения
│ -size: int                         │  число элементов
│ -INITIAL_CAPACITY: int = 4         │  начальная вместимость
├────────────────────────────────────┤
│ +GenericStack()                    │
│ +getSize(): int                    │
│ +getCapacity(): int                │
│ +isEmpty(): boolean                │
│ +peek(): E                         │
│ +push(o: E): void                  │
│ +pop(): E                          │
│ -grow(): void                      │  удваивает массив
└────────────────────────────────────┘
```

Массив удваивается, когда `size == elements.length`. Из прогона:

| push | size | вместимость |
|---:|---:|---:|
| 4 | 4 | 4 |
| 5 | 5 | **8** |
| 8 | 8 | 8 |
| 9 | 9 | **16** |
